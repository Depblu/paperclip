# Virtual Campus UI 重构需求定义

版本：v1.0  
日期：2026-06-22  
输入来源：参考截图、当前 `virtual-campus/` 实现、`todo/virtual-campus-requirements-and-technical-plan.md`

## 1. 背景与目标

Virtual Campus 是 Paperclip 的空间化运营视图。它不替代 Paperclip 的 company、agent、issue、approval、cost、activity 主数据模型，而是把这些对象投影成园区、楼宇、楼层、工位和人员状态，帮助管理者快速判断公司运行状态并钻取到原始工作对象。

本次 UI 重构目标：

1. 把当前“总览卡 + 左过滤 + Canvas 楼层 + 右抽屉”的 PoC，重构为参考图风格的高密度运营后台。
2. 明确概念、界面功能、交互、展示、风格和操作要求，供产品、设计、前端实现对齐。
3. 保留原始需求中的独立 Web 前端 + Campus BFF/Sync Service + Campus Read Model 边界。
4. MVP 仍为二维虚拟园区，不做真实 GIS、3D 数字孪生、完整 HR 系统或通用聊天。

## 2. 产品定位

| 项目 | 定义 |
|---|---|
| 产品名称 | Virtual Campus / 虚拟软件园区 |
| 核心价值 | 用空间化界面展示 AI 公司组织、任务、运行、成本、审批、告警和产物状态。 |
| 默认视角 | 管理后台视角，优先支持公司 Owner、团队负责人、平台管理员和观察者。 |
| 主界面隐喻 | 园区 -> 公司/楼宇 -> 楼座 -> 楼层 -> 工位 -> Agent/任务详情。 |
| 操作边界 | MVP 以观察、筛选、定位、钻取和跳转 Paperclip 为主；P1 再加入审批、暂停、派单和布局编辑。 |

## 3. 概念定义

| 概念 | 定义 | 数据来源 |
|---|---|---|
| 园区 Campus | 一个或多个可访问 company 的空间容器。 | Campus 扩展模型 |
| 楼宇 Building | company 的空间入口；一栋楼默认绑定一个 company。 | Campus + Paperclip company |
| 楼座 Block | 楼宇内的区域分组，如 A 座、B 座；用于承载多栋/多团队布局。 | Campus layout |
| 楼层 Floor | 工位视图容器，包含工位、区域、状态图例和过滤器。 | Campus layout |
| 工位 Seat | Agent 的空间位置；可为空、占用、离线、保留。 | Campus seat/assignment |
| 员工 Employee | MVP 中等同于 Paperclip agent；真人用户只作为管理身份，不进入工位驻留模型。 | Paperclip agent 投影 |
| 当前任务 Task | Agent 当前关联的 Paperclip issue。 | Paperclip issue 投影 |
| 活动 Activity | issue comment、run、approval、cost、agent status 等事件的规范化展示。 | Paperclip activity/live event |
| 告警 Alert | BFF 根据阻塞、错误、预算、审批等待等规则生成的 UI 提醒。 | Campus aggregation |
| 产物 Artifact | issue work product、attachment、preview link、report 等可检查输出。 | Paperclip work products |

## 4. 状态语义

状态必须分层展示，不允许用一个颜色同时表达多个含义。

| 状态层 | 示例 | 主展示位置 | UI 表达 |
|---|---|---|---|
| 工位占用 | 空闲、工作中、忙碌、离开、离线 | 工位卡/工位节点 | 卡片底部状态条、圆点、图例 |
| Agent 运行 | idle、running、paused、error | 右侧详情、工位角标 | 头像边框、状态文字、异常红点 |
| 任务状态 | todo、in_progress、blocked、in_review、done | 工位卡、任务列表 | 任务标签、阻塞角标、优先级标签 |
| 告警状态 | cost_overrun、blocked_too_long、agent_error、approval_pending | 顶部指标、右侧详情、告警列表 | 图标 + 数量 + 严重级别颜色 |

推荐颜色：

| 状态 | 颜色语义 |
|---|---|
| 工作中/running | 绿色 |
| 忙碌/in_progress | 橙色或蓝色，需与工作中区分 |
| 阻塞/异常/error | 红色 |
| 离开/offline | 灰色 |
| 审批待办 | 琥珀色 |
| 选中态 | Paperclip 品牌蓝 |

## 5. 信息架构

### 5.1 应用壳

界面采用参考图的三栏后台结构：

1. 左侧深色导航：固定宽度，承载园区总览、组织管理、工作管理、系统管理。
2. 顶部栏：面包屑、全局搜索、通知、用户菜单。
3. 主内容区：公司概览、楼层工位区、右侧详情检查器。

左侧导航分组：

| 分组 | 菜单 |
|---|---|
| 园区 | 园区总览 |
| 组织管理 | 公司管理、楼宇管理、楼层管理、工位管理 |
| 人员与组织 | 职位管理、员工管理 |
| 工作管理 | 任务管理、审批待办、产物墙 |
| 系统管理 | 权限管理、系统设置、数据同步、操作日志 |

MVP 可只实现可点击入口中的园区总览、工位视图、任务跳转和数据同步状态；未完成菜单显示为 disabled 或隐藏，不做假入口。

### 5.2 顶部栏

| 元素 | 要求 |
|---|---|
| 面包屑 | 显示“园区总览 / 公司 / 楼座 / 楼层”，刷新后可恢复。 |
| 搜索 | 支持搜索公司、Agent、工位、任务编号、任务标题。 |
| 通知 | 显示告警总数和审批待办数；点击进入告警/审批列表。 |
| 用户菜单 | 显示当前角色；支持切换观察者脱敏预览。 |

### 5.3 公司概览区

位于主内容顶部，替代当前简单 building card 列表。每次选中一个 company/building 后展示：

| 模块 | 内容 |
|---|---|
| 公司信息 | 公司名、运行状态、员工/Agent 数、创建时间、楼宇图片或占位图。 |
| 组织结构摘要 | 顶部 company 节点，下方展示团队中心和人数，如研发中心、产品中心、运营中心、测试中心、技术支持。 |
| 指标卡 | 进行中任务、阻塞任务、本月成本、审批待办。 |
| 快捷操作 | 打开 Paperclip company、打开任务列表、查看同步状态。 |

### 5.4 楼层工位区

楼层区是页面核心，使用“楼座 tabs + 楼层按钮 + 工位视图”结构：

1. 楼座 tabs：A 座、B 座、C 座。
2. 楼层切换：5 楼、4 楼、3 楼、2 楼、1 楼。
3. 过滤器：团队、搜索工位或员工、状态、优先级、告警。
4. 视图切换：卡片网格视图、平面画布视图、列表视图。
5. 状态图例：空闲、工作中、忙碌、离开、离线、异常。

MVP 默认视图为卡片网格，贴近参考图。当前 Canvas 视图保留为“平面图模式”，用于 1000 工位高密度场景。

### 5.5 工位卡

工位卡是默认展示单元。每张卡固定尺寸，避免数据变化造成布局跳动。

| 区域 | 内容 |
|---|---|
| 顶部 | 工位编号，如 A5-01；右侧选中/展开图标。 |
| 中部 | Agent 形象或工位插图；空工位显示空桌。 |
| 人员 | Agent displayName、title/role、团队。 |
| 底部状态 | 工作状态圆点、任务数、评论/活动数、告警数。 |
| 选中态 | 蓝色描边；同步右侧详情。 |

工位卡不展示敏感 payload、token、secret、账号或完整成本明细。

### 5.6 右侧详情检查器

右侧详情检查器固定在主内容右侧，宽度约 320-380px。未选中工位时显示“选择工位后查看详情”和关键告警摘要。

选中工位后展示：

| Tab | 内容 |
|---|---|
| 基本状态 | Agent 状态、任务数、阻塞数、今日提交、本月成本、在线时长、最后活跃。 |
| 当前任务 | 当前 issue、状态、优先级、阻塞信息、打开 Paperclip 链接。 |
| 活动 | 最近 timeline_event、run 摘要、approval 变化。 |
| 成本 | 本月花费、预算占比、趋势摘要；观察者只看区间或四舍五入值。 |

详情区所有外链必须跳转到 Paperclip 原始对象，不能复制 Paperclip 的完整 issue 页面。

## 6. 界面功能需求

| ID | 功能 | 优先级 | 需求 | 验收口径 |
|---|---|---:|---|---|
| UI-FR-01 | 左侧导航 | P0 | 提供园区、组织、人员、工作、系统五类入口。 | 当前可用入口可点击；未实现入口隐藏或 disabled。 |
| UI-FR-02 | 面包屑定位 | P0 | 显示园区、公司、楼座、楼层路径。 | 刷新后路径恢复；点击上级可返回。 |
| UI-FR-03 | 公司概览 | P0 | 展示公司基础信息、组织摘要、任务/阻塞/成本/审批指标。 | 指标与 BFF 聚合数据一致。 |
| UI-FR-04 | 楼座/楼层切换 | P0 | 支持楼座 tabs 和楼层按钮。 | 切换后工位区、URL 和详情状态同步更新。 |
| UI-FR-05 | 工位卡网格 | P0 | 默认以卡片展示工位、人员、岗位、状态和计数。 | 1920x1080 下首屏至少展示 8 个工位卡。 |
| UI-FR-06 | 平面图模式 | P0 | 保留 Canvas 平面图，支持缩放和选中。 | 1000 工位以内保持可交互。 |
| UI-FR-07 | 搜索过滤 | P0 | 支持团队、状态、优先级、告警、文本搜索。 | 可定位到目标工位；空结果可清空过滤。 |
| UI-FR-08 | 右侧详情 | P0 | 展示基本状态、当前任务、活动、成本四个 tab。 | 选中工位后详情即时更新。 |
| UI-FR-09 | 实时同步状态 | P0 | 展示 connected、stale、error 三种同步状态。 | 事件到达后刷新指标和工位状态。 |
| UI-FR-10 | Paperclip 跳转 | P0 | 从 company、agent、issue、work product 跳转原始对象。 | 跳转目标使用 Paperclip 原始 URL。 |
| UI-FR-11 | 权限脱敏 | P0 | 按 viewer role 裁剪字段。 | observer 无法看到敏感 payload 和精确成本。 |
| UI-FR-12 | 产物入口 | P1 | 在任务或工位详情中展示最近产物。 | 可打开 work product、attachment、preview link。 |
| UI-FR-13 | 布局管理 | P1 | 支持布局导入、导出、编辑和版本回滚。 | 布局变更可审计、可恢复。 |

## 7. 展示规则

| 场景 | 展示要求 |
|---|---|
| 加载中 | 主内容保持骨架屏或局部 loading，不清空左导航和顶部栏。 |
| 空工位 | 显示空桌插图、灰色状态和工位编号；不显示人员占位假数据。 |
| 空结果 | 显示当前过滤条件导致无结果，并提供“清空过滤”。 |
| 异常 Agent | 工位卡、详情头像和告警区同时出现异常标识，但不遮挡任务信息。 |
| 阻塞任务 | 在工位卡底部和详情当前任务 tab 显示阻塞标签。 |
| 成本数据 | company_owner 看精确值；observer 看区间或四舍五入值。 |
| 实时更新 | 使用轻量状态变化提示，不弹出打断式 toast。 |
| 选中工位 | 卡片蓝色描边，右侧详情同步，不因事件刷新丢失选中态。 |
| 多状态冲突 | 异常优先于阻塞，阻塞优先于忙碌，忙碌优先于工作中，离线优先于空闲。 |
| 移动窄屏 | 左导航折叠，右侧详情改为底部抽屉；工位卡保持可读。 |

## 8. 核心交互

### 8.1 导航与定位

1. 用户从园区总览进入 company/building。
2. 选择楼座和楼层后，URL 保存 `companyId`、`block`、`floor`、过滤条件。
3. 搜索结果点击后自动切换到目标楼层并选中工位。
4. 面包屑每一级都可点击返回。

### 8.2 搜索与过滤

搜索需支持即时过滤和回车定位。过滤条件可组合：

| 条件 | 值 |
|---|---|
| 团队 | 全部、Leadership、Engineering、Operations、Review 等 |
| 状态 | 全部、工作中、忙碌、离开、离线、异常、阻塞 |
| 优先级 | critical、high、medium、low |
| 告警 | cost_overrun、blocked_too_long、agent_error、approval_pending |

空结果展示清晰提示，并提供“清空过滤”操作。

### 8.3 工位选择

1. 单击工位卡：选中并打开右侧详情。
2. 双击工位卡：进入 Agent/工位详情页，或在 P1 中展开全屏详情。
3. 点击任务：打开当前任务 tab。
4. 点击“Open in Paperclip”：新窗口或同窗口跳转到 Paperclip issue。

### 8.4 实时刷新

界面顶部显示 live sync 状态：

| 状态 | 表达 |
|---|---|
| connected | 绿色状态，展示最新同步时间。 |
| stale | 灰色/琥珀状态，提示数据可能延迟。 |
| error | 红色状态，提供重试入口。 |

收到 SSE/WebSocket 事件后，工位状态、右侧详情、指标卡和告警数应增量刷新。刷新不能清空当前选中工位或重置滚动位置。

### 8.5 权限与脱敏

权限沿用 Paperclip company scope。Campus 不扩大可见范围。

| 角色 | 默认可见 |
|---|---|
| platform_admin | 可见所有 company 聚合与布局配置。 |
| company_owner | 可见本 company 明细。 |
| team_lead | 可见授权团队明细。 |
| observer | 只看聚合、化名、区间成本和脱敏任务标题。 |
| auditor | 可看事件和审计元数据，不默认看敏感 payload。 |

## 9. 操作需求

MVP 操作：

1. 切换 company、楼座、楼层。
2. 搜索和过滤工位、Agent、任务。
3. 选择工位并查看详情。
4. 从详情跳转 Paperclip 原始 company、agent、issue、work product。
5. 查看实时同步状态并手动刷新。
6. 使用观察者脱敏预览。

P1 操作：

1. 审批待办处理。
2. 暂停/恢复 Agent。
3. 给 Agent 派发 issue。
4. 工位布局导入、导出、编辑、版本回滚。
5. 时间轴回放、通信图谱、产物墙。

## 10. 视觉与风格

| 维度 | 要求 |
|---|---|
| 整体风格 | 专业、克制、运营后台；不做营销页、英雄区或装饰性渐变。 |
| 布局 | 深色左侧导航 + 浅色内容区 + 白色功能面板。 |
| 圆角 | 卡片和面板 6-8px；不使用过大圆角。 |
| 密度 | 支持一屏查看公司指标、楼层过滤、至少 8-12 个工位卡和右侧详情。 |
| 图标 | 使用 lucide 或现有图标库；按钮优先图标 + tooltip。 |
| 插图 | 工位卡可使用统一风格的工位/Agent 位图或生成图；空工位、离线、异常需有不同状态。 |
| 字体 | 使用系统 sans-serif；标题不过度放大；不使用随 viewport 缩放的字体。 |
| 响应式 | 桌面优先；小屏时右侧详情下沉或抽屉化，左侧导航折叠。 |

## 11. 与当前实现的关系

| 当前实现 | 重构要求 |
|---|---|
| `CampusApp` 顶部标题和 building cards | 改为左导航 + 顶部栏 + 公司概览区。 |
| 左侧 filters + metrics | 保留过滤能力，迁移到楼层工具条和左侧辅助栏。 |
| `FloorCanvas` Canvas 平面图 | 保留为平面图模式；默认新增工位卡网格视图。 |
| `SeatDrawer` 右侧详情 | 扩展为 tab 化详情检查器。 |
| SSE `openEvents` | 保留实时刷新；补充 stale/error 状态和选中态保持。 |
| shared projections | 继续使用 `CampusOverview`、`FloorView`、`FloorViewSeat`；新增 block、floor tabs、counts、activityCount 等展示字段。 |

## 12. 验收标准

1. 进入页面后能看到参考图结构：左导航、顶部栏、公司概览、楼座/楼层切换、工位区、右详情。
2. 工位卡能展示编号、人员、岗位、状态、任务/活动数量和选中态。
3. 工位详情能展示基本状态、当前任务、活动和成本，并能跳转 Paperclip 原始任务。
4. 搜索和过滤能定位到目标工位；空结果可清空过滤。
5. 实时事件到达后，指标、工位状态和详情刷新；当前选中工位不丢失。
6. observer 角色看不到敏感 payload、真实受限名称、精确成本和受限任务标题。
7. 1000 工位以内的平面图模式可交互；默认卡片模式在 1920x1080 下一屏至少展示 8 个工位卡。
8. 页面刷新后恢复 company、楼座、楼层和过滤状态。
9. UI 风格与参考图一致：高密度后台、蓝色选中态、清晰状态图例、右侧检查器，不出现营销式 hero 或装饰性背景。
